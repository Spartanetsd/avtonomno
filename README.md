# Автономно

**Рішення є. Навіть коли немає звичного.**

Офлайн-помічник (PWA) для людей, які лишилися без світла, газу, опалення, води чи зв’язку, — і для тих хвилин, коли лунає сирена. За 10–15 секунд підказує безпечне практичне рішення з того, що є під рукою, і чесно каже, коли безпечного рішення немає.

> ⚠️ Застосунок дає загальну інформацію і не замінює екстрені служби. Якщо є загроза життю — телефонуйте **112** (пожежна — 101, швидка — 103, газова — 104, поліція — 102).

## 1. Опис

### Версія 2.1: безпечніший підбір на основі 2.0

Друга версія переосмислена за принципами Стіва Джобса: фокус — це вміння сказати «ні»; найважливіше — на відстані одного дотику; простота — результат роботи, а не її відсутність; дизайн — це те, як воно працює в найгірший момент.

- **Тривога — на першому місці.** Окрема вкладка «Укриття» і великий вхід на головному екрані: що робити зараз → «Я в укритті» → «Відбій». Застосунок рахує час перебування в укритті, підлаштовує всі поради під укриття й хвалить за кожен вчасний спуск.
- **Підготовка — одна вкладка «Готовність»:** тривожна валізка, підготовка підвалу чи іншого укриття, важливі запаси — з відсотком готовності й похвалою.
- **Зайве прибрано:** вибір сезону переїхав на сторінку сценарію, «Збережене» — у «Готовність», резерв має власний екран.

Що вміє застосунок:

- **Режим «Я в укритті»:** п’ять кроків під час сирени; що робити, якщо до укриття не встигаєте (правило двох стін — лише як крайній захід), якщо тривога застала на вулиці чи в авто; таймер «Ви в укритті» в шапці; перші хвилини, поради для дітей, тварин, тепла, повітря й заряду; що робити, якщо вихід завалено; кроки після відбою. Поки режим увімкнено, підбір рішень не радить нічого з вогнем, горінням чи виходом надвір, а першими показує картки «Тепло в укритті» та «Задушливо в укритті».
- **Інструменти на весь екран:** нічник із чотирма рівнями теплого світла, «Дихаємо разом» (вдих 4 с, видих 6 с — для дітей і дорослих), звуковий сигнал «Я тут» для рятувальників (три гудки кожні 10 с на чорному екрані). Екран не гасне, поки інструмент відкритий.
- **Тривожна валізка** за переліком МОН: 34 пункти, з них дитячі й для тварин з’являються лише тоді, коли діти чи тварини є; нагадування перевіряти раз на 3 місяці.
- **Підготувати укриття:** знайти 2–3 найближчі укриття, оглянути підвал (два виходи, вентиляція, вогнегасник), облаштувати й домовитися з сусідами.
- **Пам’ятка для укриття** — один аркуш для друку з номерами, правилами й порожніми рядками для адреси та відповідальних; кнопка «Поділитися» надсилає застосунок сусідам.
- **Шість ситуацій на головному екрані:** зігрітися, приготувати їжу, знайти воду, отримати енергію, охолодитися, побут і гігієна.
- **Підбір рішень просто на пристрої**, без хмарного ШІ. Враховує місце, обладнання, резерв, обмеження, тривалість, бюджет, сезон і стан сьогодні. Показує три найкращі варіанти й пояснює, чому саме вони.
- **58 карток рішень** із 14 обов’язковими полями на чотирьох рівнях: «Без витрат», «Дешево», «Практично», «Автономна система». Перша рекомендація позначена «Найкраще зараз» і показує перші кроки одразу.
- **9 небезпечних «міфів»** — обігрів газовою плитою, генератор на балконі, мангал у приміщенні тощо. Їх можна знайти пошуком, але вони ніколи не рекомендуються й завжди ведуть до безпечної заміни.
- **Чотири сезонні сценарії** — зима, весна, літо, осінь.
- **Швидкий режим:** «Мені холодно» → «Зробіть зараз» (три дії) і вибір часу: «Є 5 хвилин», «Є 30 хвилин», «Хочу вирішити надовго».
- **Пошук розуміє розмовні слова:** «повербанк», «підвал», «бомбосховище», «свічка» (покаже безпечне світло й пояснить, чому свічка не обігрівач) і веде просто в потрібний розділ — валізку, укриття, нічник.
- **Ярлики на значку застосунку** (Android): «Укриття», «Холодно», «Валізка».
- **«Мій стан сьогодні»:** світло, газ, вода, безпечність виходу надвір, заряд, температура в кімнаті, люди й тварини. Попередження мають три рівні: «Інформація», «Обережність», «Небезпечно».
- **«Мій резерв»:** облік запасів, повний експорт та імпорт JSON (тема, калькулятори, історія укриття, валізка й підготовка).
- **Чотири калькулятори** з поясненням «Як це пораховано?»: автономність акумулятора, нагрівання води, запас води, енергетичні пріоритети (з попередженням про медичні пристрої).
- **«Пояснює фізика»:** Джоуль, Фарадей, Карно, Фур’є, Ньютон, Ейнштейн. Факт, інженерний висновок та ілюстрація подані окремо; вигаданих цитат немає.
- **10 обов’язкових правил безпеки**, екстрені номери, ознаки небезпечних станів.
- **38 ілюстрацій із підписами-підтримкою:** головний екран змінюється за порою доби, кожна ситуація й сезон мають свою картинку, а фізики показують саме ті досліди, про які розповідає картка.
- Світла, темна й **чорна** теми (чорна береже заряд на OLED-екранах і не засліплює в темряві), режим високої контрастності, зменшення анімації. Орієнтир — WCAG 2.2 AA.

Принципи: усі дані зберігаються лише на вашому пристрої. Немає трекерів, аналітики, CDN і зовнішніх шрифтів. Поради спираються на відкриті офіційні джерела (CDC, МОЗ України, ДСНС, МОН, ЮНІСЕФ, Держпродспоживслужба, Ready.gov та інші), а посилання є в кожній картці й розділі. Де офіційна сторінка недоступна, джерелом є медіа з прямим посиланням на роз’яснення ДСНС чи МВС — це вказано в назві джерела. Брендів немає.

**Користувачам** нічого встановлювати не потрібно: відкрийте адресу сайту й за бажання додайте його на початковий екран (розділ 6).

**Розробникам** знадобиться лише [Node.js](https://nodejs.org/) 20 або новіший — для локального сервера й тестів. Сторонніх бібліотек застосунок не має. TypeScript потрібен тільки для перевірки типів (завдяки lock-файлу достатньо `npm ci`):

```bash
npm ci
```

## 3. Локальний запуск

```bash
npm start              # http://localhost:5173/
npm run start:pages    # http://localhost:5173/avtonomno/ — так само, як на GitHub Pages
```

Інший порт на macOS чи Linux: `PORT=8080 npm start`.

Не відкривайте `index.html` подвійним клацанням: з адресою `file://` браузер не завантажить модулі й не запустить Service Worker.

Під час розробки Service Worker віддає файли з кешу. Щоб одразу бачити зміни, увімкніть у DevTools **Application → Service workers → Update on reload** або змініть `VERSION` у `sw.js`.

## 4. Завантаження на GitHub

### З iPhone, без комп’ютера

1. Збережіть архів проєкту у «Файли» й торкніться його — iOS розпакує його в папку.
2. На github.com натисніть **+ → New repository**, введіть назву `avtonomno`, оберіть **Public** → **Create repository**.
3. На сторінці порожнього репозиторію торкніться **uploading an existing file** (або **Add file → Upload files**).
4. **choose your files → Вибрати файли** → відкрийте розпаковану папку → **Вибрати** → позначте всі файли → **Відкрити**.
5. Унизу натисніть **Commit changes**.

Сайтова частина проєкту плоска. **Важливо:** прихована службова папка `.github/workflows/` може не завантажитися через мобільний браузер разом із файлами. Якщо публікуєте тільки з iPhone, оберіть Pages «Deploy from a branch». Для Actions створіть файл `.github/workflows/pages-deploy.yml` у вебредакторі GitHub вручну або завантажте репозиторій із комп'ютера через Git.

### З комп’ютера

```bash
git init
git add .
git commit -m "Автономно 2.1.0"
git branch -M main
git remote add origin https://github.com/USERNAME/avtonomno.git
git push -u origin main
```

`USERNAME` — ваше ім’я користувача на GitHub.

## 5. Увімкнення GitHub Pages

### Спосіб А — з гілки (найпростіший, працює з iPhone)

1. Відкрийте **Settings → Pages**.
2. **Build and deployment → Source: Deploy from a branch**.
3. **Branch: main**, папка **/ (root)** → **Save**.
4. За кілька хвилин сайт з’явиться за адресою `https://USERNAME.github.io/avtonomno/`.

Збирати нічого не потрібно: файли репозиторію — це і є готовий сайт. На безкоштовному плані GitHub публікує Pages лише з публічних репозиторіїв.

### Спосіб Б — GitHub Actions, з перевірками до кожної публікації (рекомендовано)

Файл `.github/workflows/pages-deploy.yml` уже включений до архіву 2.1. Нічого переносити не потрібно.

1. Завантажте всі файли та приховану папку `.github` у GitHub-репозиторій.
2. **Settings → Pages → Source: GitHub Actions**.
3. Після кожного push у `main` автоматично виконуються `npm ci`, `npm test`, `npm run check` і лише потім публікація.
4. Результати — вкладка **Actions**. Реальний деплой у вашому репозиторії перевірте окремо.

Оберіть один спосіб публікації. Для готовності до оновлень з тестами краще GitHub Actions.

### Власний домен

1. **Settings → Pages → Custom domain** → введіть, наприклад, `avtonomno.example.com` → **Save**.
2. У DNS-провайдера створіть для піддомену запис **CNAME** `avtonomno` → `USERNAME.github.io`. Для кореневого домену потрібні чотири записи **A**: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`.
3. Коли сертифікат буде готовий, увімкніть **Enforce HTTPS** — Service Worker працює лише через HTTPS.

Усі шляхи в застосунку відносні, тому він працює і в `/avtonomno/`, і в корені домену. Проте для браузера нова адреса — це інший сайт. Перед переїздом зробіть у «Мої ресурси» **Експорт JSON**, а на новій адресі — **Імпорт JSON**.

## 6. Встановлення на телефон (PWA)

### iPhone, iPad (Safari)

1. Відкрийте адресу сайту в Safari.
2. Торкніться **Поділитися** (у новіших iOS кнопка може бути в меню **⋯**).
3. Оберіть **На початковий екран** → **Додати**.

### Android (Chrome)

1. Відкрийте адресу сайту в Chrome.
2. Меню **⋮** → **Встановити застосунок** або **Додати на головний екран** (назва залежить від версії Chrome).
3. Підтвердьте встановлення.

Після встановлення відкрийте застосунок один раз з інтернетом і дочекайтеся на головному екрані напису **«Основні функції офлайн»**.

## 7. Як працює офлайн

- **Перший візит.** Service Worker (`sw.js`) завантажує в кеш усі 24 файли застосунку. Індикатор на головному екрані показує справжній стан: «Перевіряю офлайн-режим…» → «Кешування: N з 24» → «Основні функції офлайн». Коли мережі немає, додається «· зараз без інтернету».
- **Ілюстрації.** 38 картинок дозберігаються у фоні, щойно застосунок готовий до офлайну, — в окремий кеш. Хід видно в «Про застосунок»: «Ілюстрацій у кеші: N з 38». Якщо картинка ще не збережена, а мережі немає, застосунок просто її не показує.
- **Без мережі.** Застосунок відкривається з кешу: режим укриття, валізка, підбір рішень, картки, калькулятори, сезони й правила безпеки доступні повністю. Мережа потрібна лише для зовнішніх посилань на джерела. Екстрені номери телефонують через мобільний зв’язок.
- **Дані.** Стан, резерв, валізка, підготовка укриття, режим «Я в укритті», обране, нотатки, налаштування й значення калькуляторів зберігаються в `localStorage` цього браузера. Дані версій 1.x і 2.0 переходять у 2.1 (схема 3, міграція в `store.js`); перевірте резерв після оновлення. Нічого нікуди не надсилається — сервера в застосунку немає. Зміни між відкритими вкладками синхронізуються.
- **Оновлення.** Коли є мережа, браузер перевіряє `sw.js`. Якщо змінився `VERSION`, нова версія завантажується у фоні, а людина бачить «Доступна нова версія застосунку» з кнопкою «Оновити». Старий кеш видаляється, а дані користувача лишаються недоторканими.
- **Розробникам:** після будь-якої зміни файлів збільшуйте `VERSION` у `sw.js` (наприклад, `avtonomno-v2.0.1`). Інакше встановлені копії не оновляться. Ілюстрації живуть в окремому кеші й не завантажуються заново з кожною версією. Замінили чи додали картинку — збільште ще й `PICS_CACHE` (наприклад, `avtonomno-pics-v2`), а нову картинку впишіть у `pics.js` і в список `PICS` у `sw.js`.
- **iPhone.** Safari видаляє дані сайту разом з офлайн-кешем, якщо сайтом не користувалися протягом 7 днів роботи Safari. Застосунки на початковому екрані мають власний лічильник. Тому на iPhone встановіть застосунок на початковий екран і час від часу робіть **Експорт JSON**.

## 8. Структура бази рішень

Рішення — звичайні JavaScript-об’єкти в `solutions.js`. Довідники лежать у `data.js`, а типи всіх полів описані в `types.d.ts`.

| Поле | Зміст |
| --- | --- |
| `id` | Унікальний ідентифікатор: `heat-…`, `food-…`, `water-…`, `energy-…`, `cool-…`, `hyg-…`, `prep-…` (підготовка — лише в режимі «надовго») |
| `need` | Ситуація: `heat`, `food`, `water`, `energy`, `cool`, `hygiene` |
| `title`, `problem` | Назва й проблема, яку розв’язує рішення |
| `seasons` | Сезони: `winter`, `spring`, `summer`, `autumn` |
| `level` | 1 — без витрат, 2 — дешево, 3 — практично, 4 — автономна система |
| `cost` | Орієнтовна верхня межа витрат, грн (0 — без витрат) |
| `prepMin`, `resultMin` | Час підготовки й час до результату, хв |
| `difficulty` | Складність від 1 до 5 |
| `effect` | Внутрішня оцінка ефективності 1–5 для ранжування |
| `result` | Очікуваний результат |
| `materials` | Що знадобиться |
| `needs`, `needsAny` | Потрібне обладнання чи умови; `needsAny` — «хоча б одне з групи» |
| `uses` | Що витрачає й чим ризикує: `water` (л), `energyWh`, `flame`, `combustion`, `outside` |
| `places` | Правило для місця (`apartment`, `house`, `shelter`, `car`, `temp`): `ok`, `caution`, `danger` або `na` |
| `risk` | `info` або `caution`; рівень `danger` мають лише міфи |
| `steps` | Покрокова інструкція |
| `limits` | Обмеження й ризики |
| `altId`, `altText` | Безпечна альтернатива |
| `physics` | Фізичний принцип: `law` (`joule`, `faraday`, `carnot`, `fourier`, `newton`, `einstein`) і пояснення |
| `sources` | Ключі джерел із `SOURCES` у `data.js` |
| `now` | Коротка дія для блоку «Зробіть зараз» |
| `tags` | Слова для пошуку |
| `vulnerableRisk` | Необов’язкове попередження для дітей, літніх і хворих |

Інші частини бази:

- `MYTHS` у `solutions.js` — небезпечні поради: `title`, `why` (чому небезпечно), `instead` (безпечні рішення), `sources`.
- `SOURCES` у `data.js` — записи виду `ключ: { org, title, url }`, лише офіційні джерела й лише `https`.
- `SEASONS` у `data.js` — для кожного сезону вступ, головне правило, завдання з посиланнями на рішення й застереження.
- `RULES`, `SYMPTOMS`, `EMERGENCY` у `safety.js` — правила безпеки, ознаки небезпечних станів, екстрені номери.
- `EQUIP` і `RESERVE_CATALOG` у `data.js` — обладнання й каталог резерву. Поле `key` пов’язує запас із полем `needs` рішення.

Як працює підбір (`engine.js`):

1. **Контекст** — профіль, стан сьогодні, резерв, сезон. У режимі «Я в укритті» місце вважається укриттям, вихід надвір — небезпечним, а температура вдома не враховується; картки з тегом «укриття» отримують перевагу, а побутові «Зробіть зараз» замінюються короткими діями для укриття.
2. **Безпека** (`safetyGate`) — відкидає міфи, рішення з правилом `danger` для поточного місця, горіння в укритті, полум’я за обмеження «без вогню» й вихід надвір, коли це небезпечно.
3. **Можливість** — чи є потрібне обладнання та умови. Чого бракує, показано окремо.
4. **Час** — «Є 5 хвилин»: підготовка до 10 хв; «Є 30 хвилин»: до 45 хв; «Хочу вирішити надовго»: усе, разом із підготовкою. Сезон впливає на порядок, але не відкидає рішення: людина сама обрала потребу. Якщо потреба суперечить температурі в кімнаті (зігріватися від +24 °C, охолоджуватися нижче +20 °C), швидкі режими чесно кажуть, що зараз це не потрібно.
5. **Бюджет** — дорожчі за обраний бюджет рішення відсіюються; наявне обладнання робить рішення безкоштовним.
6. **Оцінка** — ефективність, складність, сезон, стан (холод, спека, мало води, низький заряд) і вразливі люди. Причини показано в картці.

Результат — три найкращі варіанти. Якщо безпечного варіанта немає, застосунок прямо про це каже й підказує, що допомогло б.

## 9. Як додати нову безпечну рекомендацію

1. **Джерело.** Спершу знайдіть офіційну рекомендацію (CDC, Ready.gov, МОЗ, ДСНС, органи охорони здоров’я). Додайте її в `SOURCES` у `data.js` — лише через `https`.
2. **Картка.** Скопіюйте наявне рішення тієї ж категорії в `solutions.js` і заповніть усі поля. Кроки — короткі речення з дієсловами. Правила тексту — без брендів і назв магазинів, без латинської літери «зет»; обидва правила перевіряють тести.
3. **Ризики.** Позначте все, що несе ризик:
   - горіння палива — `uses.combustion: true`, відкрите полум’я — `uses.flame: true`;
   - такі рішення мають щонайменше `risk: 'caution'` і `places` з `shelter: 'danger'` та `car: 'danger'`, а в `limits` — провітрювання й детектор чадного газу;
   - якщо потрібно виходити надвір — `uses.outside: true`.
4. **Небезпечне — у міфи.** Якщо спосіб небезпечний сам по собі, додайте його в `MYTHS` з полем `instead` — безпечними замінами.
5. **Суперечливі джерела.** Там, де ризик найвищий, беріть суворіше правило. Приклад: CDC не радить користуватися туристичним пальником у приміщенні, а ДСНС і КМДА дають правила безпечнішого використання. Тому пальник має рівень «Обережність», стоїть нижче за безпечніші варіанти, а в укритті, авто й за обмеження «без вогню» заборонений.
6. **Перевірка.** Запустіть `npm test`: тести перевірять поля, унікальність, джерела, сезони, а також те, що міфи не рекомендуються в жодній із сотень випадкових ситуацій.
7. **Публікація.** Збільште `VERSION` у `sw.js`, щоб користувачі отримали оновлення.

Шаблон картки:

```js
{
  id: 'heat-example', need: 'heat', level: 1, cost: 0,
  title: '…', problem: '…',
  seasons: ['winter'], prepMin: 5, resultMin: 15, difficulty: 1, effect: 3,
  result: '…',
  materials: ['…'],
  needs: [], uses: {}, risk: 'info',
  places: { car: 'na' },
  steps: ['…', '…'],
  limits: ['…'],
  altId: 'heat-layers', altText: '…',
  physics: { law: 'fourier', text: '…' },
  sources: ['cdcWinter'],
  now: ['…'],
  tags: ['…'],
},
```

## Відхилення від технічного завдання

ТЗ передбачало Vite + TypeScript. Натомість застосунок написано на **чистих ES-модулях без збирання**, а типи перевіряє TypeScript через JSDoc і `types.d.ts` (`npm run check`). Причини:

- проєкт має бути плоским, бо з iPhone GitHub не приймає папок, а Vite-проєкт потребує папок і кроку збирання;
- репозиторій одразу є готовим сайтом, тож збирання нічого не зламає;
- у робочому коді немає сторонніх залежностей.

Робочий процес GitHub Actions лежить у корені як `pages-deploy.yml`. Щоб він запрацював, його треба створити в `.github/workflows/` (розділ 5, спосіб Б).

## Версія 2.1.0 — зміни та обмеження

- **За замовчуванням ресурси не вгадуються:** ковдри, відро й пакети доступні лише коли їх відмічено в профілі/резерві. Невідоме — не підтверджено.
- **Нагрівання не вгадується:** станція сама по собі не кип'ятить воду. Для 230 В чайника від станції підтвердіть наявність чайника, виходу AC та введіть номінали обох пристроїв. Допуск — лише якщо потужність чайника не більша за потужність виходу станції. Додатково перевіряйте заряд, напругу, роз'єми й інструкції виробників.
- **Вихід надвір:** нове питання в «Мій стан сьогодні», три стани. «Не знаю» і «Небезпечно» блокують рекомендації, що вимагають виходу. Функція не відстежує бойову обстановку.
- **Тривога:** застосунок не надсилає офіційний сигнал відбою; перед зміною екрана підтвердіть, що перевірили офіційне повідомлення. Стан у застосунку — лише ваш власний запис.
- **Експорт JSON:** тепер містить також тему, калькулятори та історію укриттів. Активна тривога не переноситься. Старі часткові експорти приймаються.
- **Офлайн:** окремі статуси основного кешу та ілюстрацій; кнопка завантаження всіх ілюстрацій.
- **GitHub:** готовий файл `.github/workflows/pages-deploy.yml`, `.gitignore`, зафіксовані залежності через `package-lock.json`.
- **Перевірки:** модульні та регресійні тести, TypeScript; реальні рекомендації й можливість користування в небезпеці мають бути окремо підтверджені медиками та фахівцями ДСНС. Наявність статусу «офлайн» не заміняє тесту в авіарежимі на конкретному телефоні.

Для збереження попередніх даних перед зміною адреси GitHub Pages зробіть експорт JSON у старій версії застосунку, а потім імпорт у новій.
